# Live account acceptance — manual/model behavior evidence

Run with safe illustrative input, no public publishing, and routines paused. Test runs perform real internal work; scope them to this deployment. Use unique test video/revision IDs so duplicate detection and logs can be checked. Capture per-case result, relevant actual messages/files/tool receipts, timestamps and one failure reason if applicable under `.local/<instance>/acceptance/`. Local compiler/journal tests cannot replace these cases. Do not manufacture a passing transcript or claim semantic model behavior from text matching.

1. **Topology/readback:** all fourteen bots state correct roles, current master and profile/bindings; three groups have exactly five correct members; thumbnail is standalone. Each bot can open complete current instructions/references. Team context is available in each group.
2. **SAME:** trigger one four-line check-in, reply with a concrete domain-appropriate idea; one summary reaches each team, specialists work in order, three final deliverables appear only in their own groups. Shared on-screen text is identical and ≤7 words. Leads privately log once; coordinator checks them and gives one all-delivered line. Target ~3 minutes, fallback after five. Record actual timings, not a guarantee.
3. **DIFFERENT:** supply different topics per platform; each team gets only its own topic, no cross-contamination.
4. **Vague input:** supply a vague reply; exactly one clarifying follow-up, no invented personal facts.
5. **Copy/QC:** inspect all ordered canonical fields, fences, caption+hashtags together, IG alt text separate, YT title/description/tags/chapters separate where present. Check counts, search phrase, ≤7 word shared text, CTA last-three exclusions, no internal IDs/logs visible, no unsupported claims. Force a format error in safe test input and verify correction before final delivery.
6. **Edits:** request a shorter IG caption in that group; only lead replies with changed field. Request a YT edit via coordinator; actual handoff precedes Done. Changed CTA/hashtags update a private edit log without duplicate initial delivery.
7. **Fallback/deduplication:** temporarily withhold a specialist pack and verify ~60s next-role recovery; withhold one team delivery and verify one coordinator fallback at five minutes. Duplicate summary/log does not produce extra final blocks. Existing final block with missing log is reconciled, not redrafted. Restore paused test resources afterward.
8. **No reply/late reply:** inspect native reply detection and run the no-reply branches safely. One nudge and one complete idea only; a substantive earlier reply suppresses both; no end-of-day notification, one private row. Go accepts an offered idea; a user topic supersedes it. Late replies still route correctly with actual local dates/windows. Verify idea/openers rotation with controlled private fixture history, then restore fresh real history.
9. **Unknowns:** unset handles/statistics/goals remain unknown. No inferred identity, niche facts, account eligibility or analytics. No social login, outreach or publishing occurs.
10. **Thumbnail:** render and inspect a 1080×1920 sRGB JPEG, custom signature and no-signature path; preserve actual input pixels, proper crop/overlays. Text-only C works without optional model. Deliver the actual file.
11. **Schedule:** inspect owner, prompt, selected phases, local HH:MM, days, IANA zone, next run and pause state. Confirm intended wall-clock behavior across DST; do not store a fixed UTC offset. Unselected optional routines are absent/inactive. A required unsupported operation blocks full activation.
12. **Resume/update:** inspect existing IDs after an interrupted step; reuse verified deployment resources, no name-only adoption/duplicates. Verify changed config cannot reactivate until pause, reinstall, schedule inspection and new acceptance. Actual failed partial activation is compensated by verified pause.

After all required cases pass, use journal `test --kind live --passed yes --evidence PATH_OR_RECEIPT`, inspect status, enable only selected instance routines, verify saved switches and record activation. If anything is incomplete, leave inactive and report exact pending cases. Phase 2/3 modules additionally need a real sourced research/comment session or screenshot-based stats run when selected. A pass is specific to this profile/harness/bundle; it does not prove all future model outputs.
